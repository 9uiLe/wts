# wts の設計

wts は、Git worktree と線形のブランチスタックを一つのセッションとして扱う CLI である。設定の共有、セッションの作成・一覧・更新・削除を担当する。配布対象は Apple Silicon macOS で、実装には TypeScript、Bun、Commander、Clack を使用する。

利用手順は [README](../README.md)、入力と動作の受け入れ基準は [実装仕様](specification.md)、設定と命名プロトコルは [設定資料](configuration.md)、選択理由は [設計判断](decisions.md)、環境構築と公開手順は [開発資料](development.md) に記載する。

## ドメインと永続状態

セッションは一つの worktree、ルートブランチ、そのルートに属するスタックブランチで構成する。ルートのスタック番号は `1`、所属ブランチの名前は `<root>-pr<n>-<名前>` とする。スタック番号は GitHub の PR 番号とは独立している。

管理範囲は設定の `worktreeDirectory` から解決したディレクトリの配下である。worktree の名前からルートブランチを推測しない。登録済み worktree のパス、セッション識別情報、ローカル参照を使って所属を判断する。

| 状態 | 保存場所 | 内容 |
| --- | --- | --- |
| プロジェクト設定 | `.wts.json` | ベースブランチ、worktree の管理範囲、命名規則 |
| セッション識別情報 | worktree 専用 Git ディレクトリの `wts-session.json` | ルートブランチ名 |
| lease | 同じ Git ディレクトリの `restack-lease` | rebase 開始時の origin のブランチ OID |
| コピー対象 | 実行元 worktree の `.worktree-copy` | 相対パスと glob |

OID はコミットの識別子である。削除計画は検証したローカル OID を、push は保存した origin の OID を条件に使う。dirty は未コミット変更・未追跡ファイル・無視対象ファイルのいずれかがある状態で、list と discard が同じ判定を使う。stack・restack のクリーン条件は Git の通常の status に基づき、無視対象ファイルを含めない。

## 実装の構成

CLI が引数と環境変数を解決し、コマンドが操作の順序を決める。共通モジュールは、外部プロセス・Git・設定・セッション・命名・コピー・対話の境界を担当する。

| 実装 | 責務 |
| --- | --- |
| `src/cli.ts` | コマンド定義、入力解決、エラーとキャンセルの終了処理 |
| `src/commands/` | コマンドごとの検証、対象提示、確認、操作、結果報告 |
| `src/process.ts` | 実行ファイル・引数配列・作業ディレクトリ・標準入力による同期／非同期実行 |
| `src/git.ts` | Git の文字列取得、worktree 列挙、作業状態とベース参照の検査 |
| `src/git-version.ts` | バージョン解析と `--update-refs` の対応判定 |
| `src/path.ts` | 同一パスまたは子孫パスの判定 |
| `src/project.ts` | 実行元とメインチェックアウトの特定、設定の読込、ベース参照の解決 |
| `src/config.ts` | 設定の構造・値・パス・実行権限の検査と初期化 |
| `src/session.ts` | セッション識別情報の読書き、所属ブランチの列挙 |
| `src/naming.ts` | 既定名の生成、命名スクリプトの入出力、名前の検証 |
| `src/copy.ts` | コピー一覧の読込、副作用のない走査、配置直前の検査とコピー |
| `src/prompts.ts` | 入力可能性の判定、入力・確認・キャンセル |
| `src/terminal.ts`、`src/ui.ts` | 出力先ごとの装飾判定、表示と非同期処理中の進捗 |
| `src/skills.ts`、`src/version.ts` | バイナリに含める操作ガイド・スキルとバージョン |

外部プロセスの実行は `src/process.ts` に集約する。標準出力・標準エラーの末尾空白は実行器で保持し、Git の `run`・`tryRun` とその非同期版で除去する。cleanup の patch-id 比較は実行器の生出力を使う。doctor と命名スクリプトも同じ実行器を使用する。

worktree の path・branch・locked は一回の `git worktree list --porcelain -z` から取得する。削除時の再検証では新しい一覧を取得する。パス包含関数は同一パスを含むため、管理範囲のルート自体を除外する判断、symlink の正規化、書き込み権限、セッション情報の有効性は呼び出し元が検査する。

## 設定と実行モード

設定は実行中の worktree、メインチェックアウトの順に探索し、最初の一つを使用する。複数の設定はマージしない。`baseBranch` はローカル名であり、cleanup の保護対象と `origin/<baseBranch>` の取り込み判定を同じ設定から導出する。

start・restack の通常実行は、CLI、環境変数、明示された設定の順でベースを解決する。未指定なら対話で入力し、ローカルの `origin/HEAD`、なければ `origin/main` を候補とする。init は明示されたベースだけを保存する。cleanup は設定から解決し、省略時は `main` と `origin/main` を使う。

stdin と stdout の両方が TTY の場合に対話できる。否定と Ctrl-C は正常終了とし、必要な入力を取得できない非対話実行はエラーとする。`DRY_RUN`・`PUSH`・`PUSH_ONLY` は値が `1` の場合だけ有効で、解除は unset とする。

`--dry-run` は wts による fetch、参照・worktree・コピー先・セッション情報・lease の変更、push を抑止する。PR 情報とリモート参照の照会、設定された命名スクリプトの実行は行う。

## セッションの作成と一覧

start はベースと名前を確定し、ブランチ・パスの衝突、コピー一覧の読み込みを作成前に検査する。作成順序は worktree とブランチ、セッション情報、コピーとする。失敗時に自動 rollback は行わず、Path、ブランチ、worktree とセッション情報の作成状態を表示する。

コピーの走査は dry-run と本実行で共有する。symlink、特殊ファイル、`.git`、コピー元・配置先の境界外を拒否する。dry-run は拒否予定を表示し、本実行は警告して項目をスキップする。書き込み直前にも配置先を検査する。

stack はクリーンな作業ツリーとスタック先端での実行を要求し、未使用のスタック番号と名前でブランチを作成する。

list は管理範囲内の登録済み worktree をローカル読み取りだけで列挙する。有効なセッションは path・ルート・スタック・現在ブランチ・dirty を表示し、手作業の worktree と壊れたセッション情報は未管理として示す。通信と JSON 出力は行わない。

## スタックの更新

restack は線形で、所属ブランチが他の worktree で使用されていないスタックを対象とする。非対話の実変更は `--push` または `PUSH=1` を要求し、指定がなければ fetch・lease 保存・rebase の前に拒否する。push 対象の有無にかかわらずこの条件を適用する。

通常実行は origin の OID を lease として保存してから rebase する。rebase 後の OID で push 対象を選び、明示的な lease を指定した atomic push を行う。成功時に lease を除去する。

対話の push 確認は rebase 後に行う。否定・Ctrl-C では更新済みのローカル参照と lease を保持する。rebase が進行中でなければ、終了時に元の checkout ブランチへ復帰する。

`--push-only` は保存済み lease を必須とし、ベース解決・fetch・rebase・lease 再取得を行わない。競合を解消した後や push を見送った後の再開に使用する。

## マージ済みブランチの整理

cleanup の削除根拠は同じ GitHub リポジトリのマージ済み PR とローカル変更の取り込みである。セッション情報だけを根拠にしない。fork の PR、設定のベース、実行中のブランチ、管理範囲外の worktree で使用中のブランチを保護する。

分類は head OID の一致、ベースへの祖先関係、書き換え後のパッチ一致を使用する。パッチ比較は末尾空白を含める。書き換え後の比較では、origin のブランチ残存、未 push の tip、独自 merge commit、比較失敗を自動削除の拒否理由とする。

削除計画は `{branch, oid, path}` を保持する。提示後に dry-run で終了するか、対話承認または `--yes` を受けて次の順で処理する。

| 段階 | 検証と操作 |
| --- | --- |
| 再検証 | OID、登録済み worktree の path と branch、実行中ブランチを再取得し、計画との対応を確認する |
| worktree 削除 | 対象があれば強制削除し、失敗時はその参照を削除しない |
| 参照削除 | worktree の使用状況を再取得し、未使用なら計画の OID を期待値として原子的に削除する |
| 設定除去 | 参照削除に成功したブランチのローカル設定を除去する。設定がなければ成功とする |
| prune | 登録情報を整理する |

失敗は対象、パス、段階、診断として蓄積する。prune の失敗でも、それ以前の失敗と完了済み件数を報告する。設定除去の失敗は「参照削除済み・設定残存」と示す。外部診断はそのまま表示しない。

OID の照合と参照削除は原子的だが、worktree の検査と削除を含む全体はトランザクションではない。最終検査後の並行 checkout まで排除する保証は設けない。強制削除した worktree の未コミット・管理外ファイルは保持されない。

## セッションの破棄

`discard <path>` は利用者が指定したセッションを、マージ状況によらず破棄する。メイン・実行中・管理範囲外・未管理・ロック中の worktree、ベースブランチ、別 worktree で使用中の所属ブランチを保護する。

計画には worktree、所属ブランチと OID、HEAD、dirty を含める。`--remote` 指定時は単一の push 先にある同名ブランチと OID も取得する。リモート名を省略した場合は通信しない。dirty の破棄は `--force`、確認省略は `--yes` を要求する。承認後に計画を再取得し、状態が変わっていれば実行前に停止する。

| 段階 | 操作 | 失敗時の状態 |
| --- | --- | --- |
| リモート参照 | lease 付き atomic push で削除 | ローカルは保持。通信障害ではリモートの結果が不明な場合がある |
| worktree | `--force` の指定に応じて削除 | ローカルブランチは保持。完了したリモート削除は戻さない |
| ローカル参照 | OID 条件付きトランザクションで削除 | worktree は削除済み、ブランチと設定は保持 |
| ブランチ設定 | 削除したブランチの設定を除去 | worktree と参照は削除済み、未処理の設定は残る |

各段階の成功を確認して次へ進む。リモート照会・push・worktree 削除は非同期に実行し、進捗を表示する。認証情報を含み得る push URL とリモートの外部診断は表示しない。

## 端末 UI と診断

通常の結果は stdout、警告・エラー・進捗は stderr に出力する。Chalk は装飾、Ora は待機中の進捗、Clack は入力を担当する。出力先ごとに TTY・CI・`TERM=dumb` と色設定を判定する。`NO_COLOR` は `FORCE_COLOR` より優先する。対話可能性と装飾可能性は別に判定する。

スピナーは処理結果にかかわらず停止し、結果表示と入力の前に端末を復元する。色なしでも文言と記号で意味を伝える。表示用の手動コマンドは `commandLine()` で引数を安全に引用する。

doctor の実行情報表示は外部コマンドを要求しない。`--check` は OS・Git・gh と認証を検査し、Claude CLI は Claude 用命名スクリプトの任意要件として案内する。config check は設定とパス、ベース、命名方式を表示し、命名スクリプトを実行しない。

## AI 向けスキル

`skills get wts-cli` はバイナリに含めた操作ガイドを返す。`skills install wts-cli` はガイド取得の入口である `SKILL.md` を指定した親ディレクトリへ配置する。Git リポジトリ、設定、外部コマンド、実行時のソースファイル、通信を必要としない。

同内容なら変更せず成功する。異なる内容の置き換えは `--force` を要求し、他のファイルを保持する。配置先ディレクトリの symlink と、通常ファイル以外の `SKILL.md` を拒否する。

## 検証基盤と UI カタログ

`tests/helpers/` は一時 Git リポジトリ、ローカル bare origin、Git 設定と wts 環境変数の隔離、CLI 実行を提供する。テストは出力・終了コード・参照・worktree・設定・lease を観測する。外部サービスの応答と障害はテスト用コマンドで再現する。

UI カタログは実 CLI の端末出力と入力前画面を収録し、日付・UUID・一時パス・OID・スピナー更新回数を正規化して基準と比較する。文言・色・入力・終了コードは比較対象とする。分類は収録ケースのコマンドから導出する。

HTML は全件と変更件を切り替え、検索とコマンドで絞り込める。基準 JSON は表示確認後に明示的に採用する。収録失敗と未実測の条件は診断ファイルに記載する。

## インストールと公開判定

Web とローカルの両インストーラーは、バイナリ・SHA-256・`BUILD_INFO` を検証してから配置する。配置先の wts は通常ファイルかつ非 symlink を要求し、同一ディレクトリの staging から rename する。検証・配置失敗時は既存ファイルを保持する。シェル設定・認証・Gatekeeper 設定は変更しない。

開発ツールは Nix Flakes、JavaScript / TypeScript 依存は Bun で固定する。開発・CI の検証は同じスクリプトを入口とする。ビルドは `bun-darwin-arm64` 向けで、バージョンを埋め込み、起動と成果物の整合を検査する。

リリース検査は API 応答を `unknown` として受け取り、使用する型と構造を検証する。ビルド対象と最新 master の一致、最新公開 Release との差、バージョン・タグの未使用を要求する。API 失敗を初回公開として扱わない。

最低対応 macOS、署名・公証方針、Gatekeeper を含む配布経路の検証は正式公開の条件である。自動公開は検証用 Pre-release とし、正式公開の条件と公開手順は [開発資料](development.md#正式リリースの条件)に従う。
