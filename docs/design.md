# wts の設計

wts は、Git worktree と線形のブランチスタックを一つのセッションとして扱う。本書は、実装を変更するときに守るドメインの境界と安全契約を定義する。

## ドメインと永続状態

セッションは一つの worktree、ルートブランチ、そのルートに属するスタックブランチで構成する。ルートのスタック番号は `1`、所属ブランチの名前は `<root>-pr<n>-<名前>` とする。スタック番号は GitHub の PR 番号とは独立している。

管理範囲は設定の `worktreeDirectory` 配下であり、そのルート自体は含めない。ブランチとディレクトリを別々に命名できるよう、所属は worktree の名前から推測せず、登録されたパス、セッション識別情報、ローカル参照で判断する。手作業の worktree と壊れた識別情報は未管理として一覧に示し、stack・restack・discard の対象にしない。

| 状態 | 保存場所 | 用途 |
| --- | --- | --- |
| プロジェクト設定 | `.wts.json` | ベースブランチ、管理範囲、命名規則 |
| セッション識別情報 | worktree 専用 Git ディレクトリの `wts-session.json` | ルートブランチの識別 |
| lease | 同じ Git ディレクトリの `restack-lease` | rebase 開始時の origin のブランチ OID |
| コピー対象 | 実行元 worktree の `.worktree-copy` | コピーする相対パスと glob |

OID はコミットの識別子であり、削除や push の競合検出に使う。list と discard の dirty 判定には、未コミット変更・未追跡ファイル・無視対象ファイルを含める。一覧から破棄に必要な指定を判断できるよう、両者は同じ判定を使う。stack・restack のクリーン条件には無視対象ファイルを含めない。

設定探索、ベースの選択、命名とコピーの入力契約は [設定資料](configuration.md) に定義する。

## 責務と外部境界

CLI は引数と環境変数を解決し、コマンドは対象の検証と操作順序を担う。Git・設定・命名・コピー・対話はそれぞれの境界で扱う。操作順序と失敗後の状態をドメインの関数から読める構成とし、DI コンテナ、汎用の Plan/Executor 階層、イベントバスは使わない。

CLI 本体の外部プロセス実行は `src/process.ts` に集約し、実行ファイルと引数配列で渡す。doctor と命名スクリプトも対象とし、テスト用コマンドと開発スクリプトはこの集約範囲に含めない。外部 JSON は `unknown` として受け、利用する型と構造を境界で検証する。この検証のために大規模な schema ライブラリは導入しない。

worktree のパス・ブランチ・ロック状態は同じ一覧から判断し、変更前の再検証では取得し直す。パス包含の判定だけで操作を許可せず、管理範囲のルート除外、symlink、書き込み権限、セッション識別情報を操作に応じて検査する。

`--dry-run` は wts による fetch、参照・worktree・コピー先・セッション情報・lease の変更、push を抑止する。PR 情報とリモート参照の照会、設定した命名スクリプトの実行は行う。

## 作成とコピー

start はベースと名前、ブランチ・パスの衝突、コピー一覧の読み込みと構文を worktree 作成前に検査する。コピー一覧がなければコピー対象なしとし、存在する一覧を読めなければ作成を始めない。

worktree とブランチを作成してからセッションを記録し、コピーを行う。作成後の失敗では自動 rollback を行わず、Path、ブランチ、worktree とセッション情報の作成済み範囲を報告する。

worktree 外や Git 管理情報への書き込みとディレクトリの循環を防ぐため、コピーでは symlink、特殊ファイル、`.git`、コピー元・配置先の境界外を拒否する。dry-run と本実行は同じ副作用のない走査で判定し、書き込み直前にも配置先を検査する。dry-run は拒否予定を表示し、本実行は該当項目を警告してスキップする。拒否対象があるだけでは操作全体を失敗にしない。

stack はクリーンな作業ツリーとスタック先端での実行を要求し、未使用のスタック番号と名前でブランチを作る。

## スタックの更新

restack は線形で、所属ブランチが他の worktree で使用されていないスタックを対象とする。非対話の実変更には `--push` または `PUSH=1` を要求し、指定がなければ fetch・lease 保存・rebase の前に拒否する。push 対象がない場合も同じ条件とし、確認できないままローカル参照だけを更新しない。

通常実行では origin の OID を lease として保存してから rebase する。rebase 後の OID で push 対象を選び、保存した OID を明示した lease と atomic push を使う。これにより rebase 開始後の他者の更新を上書きせず、複数ブランチの一部だけを push しない。リモート照会や保存情報に不足があれば push を中止する。

対話の push 確認は rebase 後に行う。否定・Ctrl-C は正常終了し、更新済みのローカル参照と lease を保持する。push 成功時には lease を除去する。rebase が進行中でなければ、終了時に元の checkout ブランチへ復帰する。

`--push-only` は保存済み lease を必須とし、ベース解決・fetch・rebase・lease 再取得を行わない。競合や push 見送り後も、他者の更新を検出する基準を取り直さない。利用者向けの [再開手順](../README.md#rebase-と-push-の再開) を参照する。

## マージ済みブランチの整理

cleanup の削除根拠は、同じ GitHub リポジトリのマージ済み PR とローカル変更の取り込みである。セッション識別情報だけを根拠にしない。fork の PR、設定のベース、実行中ブランチ、管理範囲外の worktree で使用中のブランチを保護する。

取り込みは head OID の一致、ベースへの祖先関係、書き換え後のパッチ一致で判定する。パッチ比較には末尾空白も含める。書き換え後の比較では、origin のブランチ残存、未 push の tip、独自 merge commit、比較失敗を自動削除の拒否理由とする。

通常実行では候補の分類前に設定のベースを fetch するため、削除確認より前でもリモート追跡参照が変わり得る。削除対象の提示後、対話承認または `--yes` を受けて削除する。

分類で検証したブランチ・OID・worktree の対応を計画に保持し、削除前に現在の状態と照合する。対応が変わった対象は削除しない。worktree の強制削除に失敗したらその参照を残し、成功後も使用状況を再取得してから、計画の OID を条件に参照を原子的に削除する。ブランチ設定は参照削除に成功したものだけを除去し、設定がなければ成功とする。

失敗は対象・パス・段階を区別し、完了済み件数と残存対象、手動操作の案内を報告する。prune に失敗しても先行する失敗を隠さず、設定除去の失敗は「参照削除済み・設定残存」と示す。認証情報を含み得る外部診断はそのまま表示しない。

OID の照合と参照削除は原子的だが、worktree の検査と削除を含む全体はトランザクションではない。最終検査後の並行 checkout まで排除する保証は設けない。強制削除した worktree の未コミット・管理外ファイルは保持されない。

## セッションの破棄

discard は、利用者がパスで指定したセッションをマージ状況によらず破棄する。取り込みを証明して整理する cleanup とは判断根拠が異なる。メイン・実行中・管理範囲外・未管理・ロック中の worktree、ベースブランチ、別 worktree で使用中の所属ブランチを保護する。

計画には worktree、所属ブランチと OID、HEAD、dirty を含める。`--remote` 指定時は、その push 先にある同名ブランチと OID も含める。照会先と削除先を一致させ、複数の push 先を持つリモートは、atomic push で全送信先を保護できないため拒否する。リモートを指定しなければ通信しない。

dirty なファイルの破棄には `--force`、確認省略には `--yes` を要求する。確認省略だけで未保存の内容を失わないよう、両者を分ける。承認後に計画を取り直し、一致しなければ削除を始めない。

各段階の成功を確認してから次へ進む。リモートで拒否されたときに作業と再実行手段を残すため、ローカルの削除はリモート処理の成功後に行う。

| 段階 | 操作 | 失敗時の状態 |
| --- | --- | --- |
| リモート参照 | OID を指定した lease 付き atomic push で削除 | ローカルは保持。通信障害ではリモートの結果が不明な場合がある |
| worktree | `--force` の指定に応じて削除 | ローカルブランチは保持。完了したリモート削除は戻さない |
| ローカル参照 | OID 条件付きトランザクションで削除 | worktree は削除済み、ブランチと設定は保持 |
| ブランチ設定 | 削除したブランチの設定を除去 | worktree と参照は削除済み、未処理の設定は残る |

認証情報を含み得る push URL とリモートの外部診断は表示しない。

## 端末 UI

入力可能性と装飾可能性は別に判定する。対話は stdin と stdout の両方が TTY の場合に行い、必要な入力を取得できなければエラーにする。否定と Ctrl-C は正常終了とする。

通常の結果は stdout、警告・エラー・進捗は stderr に出力する。出力先ごとの色設定と端末条件を共有し、色なしでも文言と記号で意味を伝える。`NO_COLOR` は `FORCE_COLOR` より優先する。

待機中の描画と端末入力を処理できるよう、時間のかかる外部操作は非同期に実行する。スピナーは成功・失敗にかかわらず停止し、結果表示と入力の前に端末を復元する。表示する手動コマンドも引数を安全に引用する。

## インストーラー

Web・ローカルとも、成果物を検証してから配置先と同じディレクトリの staging を rename して配置する。配置先の wts は通常ファイルかつ非 symlink を要求し、検証・配置失敗時は既存バイナリを保持する。利用者の既存設定とセキュリティ判断を保護するため、シェル設定・認証・Gatekeeper 設定は変更しない。

成果物の検証方法と公開条件は [開発資料](development.md) に定義する。
