# wts の実装仕様と受け入れ基準

本書は、wts のコマンド、共通処理、検証基盤が満たす契約を定義する。実装とテストの受け入れ基準として使用する。

利用手順は [README](../README.md)、責務と不変条件は [設計書](design.md)、選択理由は [設計判断](decisions.md)、設定と命名プロトコルは [設定資料](configuration.md)、開発と公開の手順は [開発資料](development.md) に記載する。

## 目的と対象

wts は、Git worktree とブランチのスタックを使うセッション管理 CLI である。本仕様は、削除対象の検証、非対話実行、Git 境界の共通処理、初期設定から一覧・整理までの利用手順を対象とする。

実装は TypeScript、Bun、Commander、Clack を使用し、配布対象は Apple Silicon macOS とする。開発と検証には Nix devShell の固定された Bun を使用する。依存と公開の条件はリポジトリの [作業規約](../AGENTS.md) に従う。

## 用語と永続状態

| 用語 | 定義 |
| --- | --- |
| セッション | 一つの worktree、ルートブランチ、そのルートに属するスタックブランチからなる作業単位 |
| ルートブランチ | セッションを開始したブランチ。スタック番号は `1` |
| スタック番号 | セッション内のブランチの順序を表す番号。GitHub の PR 番号とは独立している |
| 管理範囲 | 設定の `worktreeDirectory` から解決したディレクトリの配下 |
| OID | Git オブジェクトの識別子。削除と push の検証には対象ブランチのコミット OID を使う |
| lease | rebase 開始時に保存する origin のブランチ OID。push 時の競合検出に使う |
| dirty | 未コミット変更、未追跡ファイル、無視対象ファイルのいずれかがある状態。`list` と `discard` で同じ判定を使う |

プロジェクト設定は `.wts.json`、コピー対象は実行元 worktree の `.worktree-copy` に記述する。セッション識別情報 `wts-session.json` と lease ファイル `restack-lease` は、それぞれの worktree 専用の Git ディレクトリに保存する。worktree の名前からセッションのルートブランチを推測しない。

スタックブランチの名前は `<root>-pr<n>-<名前>` とする。CLI オプションは `--pr-number`、環境変数は `PR_NUMBER`、命名スクリプトへの入力は `prNumber` を使用する。ヘルプ・対話・エラーでは「スタック番号」と表記し、GitHub の PR 番号とは異なることを説明する。

## 構成と共通処理

CLI は入力を解決してコマンドに渡し、コマンドは操作の順序を決める。Git・設定・命名・対話・コピーの共通処理は、それぞれの責務に従って呼び出す。DI コンテナ、汎用的な Plan/Executor 階層、イベントバスは使用しない。

| 責務 | 設計 |
| --- | --- |
| CLI 入力 | Commander で引数と環境変数を解決し、コマンドへ渡す。エラーとキャンセルの終了処理を受け持つ |
| プロセス実行 | 実行ファイル、引数配列、作業ディレクトリ、標準入力を受け取る共通実行器を使用する。標準出力・標準エラーの末尾空白を保持する |
| Git 操作 | `Git` の文字列取得 API（同期・非同期の `run`・`tryRun`）で末尾空白を除去する。patch-id 用の差分は共通実行器から空白を保持したまま受け渡す |
| worktree 一覧 | `git worktree list --porcelain -z` を解釈し、path・branch・locked を一つの取得結果から返す。状態の再検証では新しく取得する |
| パス包含 | 共通関数は「同一または子孫」を判定する。同一パスの除外、symlink の正規化、書き込み可能性、セッション情報の存在は呼び出し元で検証する |
| Git バージョン | バージョン文字列の解釈と Git 2.38 以降の `--update-refs` 可否を共有し、doctor と restack が同じ判定を使用する |
| 対話 | stdin と stdout の両方が TTY の場合に入力可能とする。判定は `prompts.ts` に置く |
| 端末装飾 | 出力先ごとに TTY、CI、`TERM=dumb`、色設定を判定する。対話可能性とは別に扱う |
| 進捗 | 待機中の描画と端末入力を処理できるよう、時間のかかる外部操作を非同期に実行し、`ui.task` で進捗を表示する |

CLI 本体の `Bun.spawn`・`Bun.spawnSync` 呼び出しは共通実行器に置く。cleanup の patch-id 経路、doctor の診断コマンド、命名スクリプトもこの実行器を使う。テスト用コマンドや開発スクリプトのプロセス実行はこの集約範囲に含めない。

命名スクリプトは指定された作業ディレクトリで JSON を標準入力から受け取り、名前を一行で返す。非ゼロ終了・空出力・複数行・不正な名前では操作を中止する。失敗時に既定名へ置き換えない。doctor と命名処理は、外部コマンドの診断をそのまま利用者へ出力しない。

## 入力と実行モード

boolean 環境変数は値が `1` の場合に有効とする。解除には unset を使用する。各コマンドのヘルプに、対応する環境変数とこの解釈を記載する。

| 環境変数 | 対応する CLI オプション | 意味 |
| --- | --- | --- |
| `DRY_RUN` | `--dry-run` | 変更を行わず実行予定を表示する |
| `PUSH` | `--push` | restack の push 確認を省略する |
| `PUSH_ONLY` | `--push-only` | 保存済み lease を使って restack の push を再開する |

コマンドは環境変数解決後の値で実行条件を判定する。外部入力はシェル文字列へ連結せず、引数配列で渡す。表示用の手動コマンドは `commandLine()` で組み立てる。

`--dry-run` は wts による fetch、ブランチ・worktree・ファイル・セッション情報・lease の変更と push を抑制する。PR 情報とリモート参照の照会、命名スクリプトの実行は許容する。対話の否定と Ctrl-C は正常終了として扱う。必要な入力を取得できない非対話環境ではエラー終了する。

## コマンドの設計

### cleanup: マージ済みブランチの整理

cleanup は、マージ済み PR とローカル変更の取り込みを証明できるブランチを整理する。削除根拠は PR とコミットの照合であり、セッション識別情報だけを根拠にしない。設定で解決したローカルのベースブランチ、実行中ブランチ、管理範囲外の worktree で使用中のブランチは対象から除外する。fetch・祖先判定・パッチ一致は、設定のベースに対応する同じ origin 参照を使用する。

マージ済み PR は候補ブランチごとに照会する。head の所属リポジトリと OID を検証し、fork の PR を削除根拠にしない。tip の一致・祖先判定・書き換え後のパッチ一致で取り込みを検証する。パッチ比較は末尾の空白も含める。書き換え後の比較では、origin のブランチ残存、未 push の tip、独自 merge commit、比較失敗を自動削除の拒否理由とする。

削除計画は `{branch, oid, path}` を保持する。`oid` は分類時に証明したコミット、`path` は対象 worktree がある場合のパスとする。利用者に対象を提示し、`--dry-run` では終了する。実行には対話の承認または `--yes` を要求する。

対象ごとの削除順序は次のとおりとする。

1. worktree 削除前に OID、登録済み worktree の path と branch、実行中ブランチを再取得する。計画との対応が変わった場合、対象の削除を開始せず報告する。
2. 対象 worktree があれば強制削除する。ロック等により失敗した場合、その対象の参照削除へ進まない。未コミット・管理外ファイルの保持は保証しない。
3. 参照削除前に worktree の使用状況を再取得し、対象ブランチが使用中なら削除しない。計画の OID を期待値として、照合と参照削除を原子的に行う。
4. 参照削除に成功したブランチのローカル設定 `branch.<名前>` を除去する。設定がなければ成功として扱う。参照削除に失敗したブランチの設定は保持する。

OID の条件付き削除は、照合した OID と削除する OID の一致を保証する。worktree の使用状況検査・worktree 削除・参照削除は一つのトランザクションではない。最終検査後の並行 checkout まで原子的に排除する保証は設けず、競合を検出した段階でその対象の処理を止める。

失敗は `{branch, path, phase, diagnostic}` として蓄積する。段階は再検証、worktree 削除、参照削除、ブランチ設定除去、prune を区別する。対象の処理と prune を終えた後、完了済み件数、残存対象、手動コマンドを報告する。設定除去失敗は「参照削除済み・設定残存」と示す。prune の失敗でも、それまでの失敗一覧を表示する。認証情報を含みうる外部診断はそのまま表示しない。

### restack: スタックの更新と push

restack は、線形で他の worktree で使用されていないスタックを更新する。CLI 入力を解決した時点で、非対話かつ非 dry-run かつ push 確認省略の指定がない場合は、fetch・lease 保存・rebase の前にエラー終了する。push 対象がゼロの場合にも適用する。再実行方法には `--push` を示す。`PUSH=1` も確認省略の指定として扱う。

通常実行では、ベース参照を確定し、origin の OID を lease として保存してから rebase する。rebase 後の OID で push 対象を選び、保存した OID を明示的な lease とする atomic push を行う。非対話の実変更には `--push` または `PUSH=1` が必要であり、rebase だけを行う非対話モードは設けない。

`--push-only` は保存済み lease を読み、rebase と lease の再取得を行わずに push を再開する。lease または必要なブランチの記録がなければ拒否する。成功時は lease ファイルを除去する。

対話では rebase 後に push を確認する。肯定なら push し、否定・Ctrl-C なら rebase 後のローカル参照と lease を保持して正常終了する。rebase が進行中でなければ、終了時に元の checkout ブランチへ復帰する。競合時の復旧は rebase の解決後に保存済み lease で push を再開する手順とする。

### start: セッション作成と管理外ファイルのコピー

start は名前とベースを確定し、ブランチ・パスの衝突と `.worktree-copy` の読み込み・構文処理を worktree 作成前に行う。リストが存在しない場合はコピー対象なしとし、存在するリストを読めない場合は作成前にエラー終了する。

作成順序は worktree とブランチの作成、セッション識別情報の記録、管理外ファイルのコピーとする。作成後に失敗した場合は、自動 rollback を行わず、worktree の Path、ブランチ、セッション記録の作成済み範囲と失敗を表示する。

コピー対象の列挙と安全性判定は、副作用のない走査として dry-run と本実行で共有する。シンボリックリンク、特殊ファイル、`.git`、コピー元・配置先の境界外を拒否する。書き込み直前にも配置先を検査する。dry-run は拒否対象を「本実行で拒否」と示し、本実行は該当項目を警告付きでスキップする。コピー対象に symlink が含まれるだけではコマンド全体を失敗にしない。

### discard: セッションの破棄

discard は、指定したセッションをマージ状況によらず破棄する。対象 worktree、所属ブランチと OID、HEAD、dirty、指定リモートの削除対象を計画に含める。メイン・実行中・管理範囲外・未管理・ロック中の worktree、ベースブランチ、別 worktree で使用中の所属ブランチを保護する。

dirty なファイルの破棄には `--force`、確認省略には `--yes` を要求する。確認後に計画を再取得し、対象・参照・ファイル状態が変わっていれば実行前に停止する。削除順序はリモート参照、worktree、ローカル参照、ブランチ設定とする。リモートは lease 付き atomic push、ローカル参照は OID 条件付きトランザクションで削除する。

リモート照会・push・worktree 削除は非同期に実行し、`ui.task` で進捗を表示する。各段階の成功を確認して次に進み、失敗時は完了範囲と残存対象を報告する。リモート指定がなければ通信しない。

### init・config check・ベース入力

`init --base-branch <name>` は、ローカルブランチ名として検証した値を `.wts.json` の `baseBranch` に保存する。`init` の生成内容は `worktreeDirectory` と空の `naming` を基本とし、ベースを指定しなければ `baseBranch` を保存しない。既存の設定は上書きしない。

ベース指定なしの init は、ローカルの `refs/remotes/origin/HEAD` があれば候補を案内する。候補は自動保存しない。`baseBranch` は cleanup の保護対象と取り込み判定にも使用するため、リモートの既定ブランチだけでは作業基準を確定できない。

start・restack のベースは、`--base-branch`、`BASE_BRANCH`、明示された設定の `baseBranch` に対応する origin 参照の順に解決する。指定がなければ対話で入力する。対話の既定候補はローカルの `origin/HEAD` が指す参照とし、なければ `origin/main` とする。

cleanup のベースは設定から解決し、`baseBranch` 省略時は `main` を保護して `origin/main` を取り込み判定に使う。`BASE_BRANCH` は cleanup の基準を変更しない。

`config check` は設定と worktree のパス、解決済みのベース、命名方式を表示する。ベース省略時は start・restack が入力を要求する旨と、cleanup の基準を区別して示す。命名方式は branch と worktree それぞれのスクリプトパスまたは既定の方式を示す。設定検査で命名スクリプトは実行しない。

### list: セッション一覧

`wts list` は管理範囲内の登録済み worktree をローカル読み取りだけで一覧する。有効な `wts-session.json` を持つセッションについて、path、ルートブランチ、スタック、現在のブランチ、dirty を表示する。手作業の worktree と壊れたセッション情報は「未管理」として表示する。

dirty の判定は discard が `--force` を要求する条件と共有する。一覧を見ればファイルの破棄に必要なオプションを判断できるようにする。通信と JSON 出力は行わない。

### doctor: 環境診断

doctor は実行情報を表示し、`--check` で OS、Git、GitHub CLI と認証を検査する。命名スクリプトは任意の実装を使用できるため、Claude CLI は Claude 用スクリプトを選んだ場合の任意要件として説明する。既定の命名は外部の命名ツールを必要としない。

## 開発・配布用処理

UI カタログは収録ケースからコマンド分類を導出する。discard と skills のケースを含め、コマンド固有のケースはそれぞれの分類で表示する。

リリース検査と cleanup が取得する JSON は `unknown` として受け取り、利用するフィールドの型と構造を明示的に検証する。不正な応答を未検証のプロパティ参照へ流さない。検証のための大規模な schema ライブラリは導入しない。

ローカルインストーラーは成果物を検証し、配置先の wts が存在する場合は通常ファイルかつ非 symlink であることを要求する。配置は staging から rename する。検証・配置に失敗した場合は既存の実行ファイルを保持する。Web インストーラーも同じ配置先保護を適用する。

## テストと受け入れ基準

### 共通テスト基盤

`tests/helpers/` は一時 Git リポジトリとローカル bare origin の生成、Git 設定を隔離した環境、wts の環境変数を除去した CLI 環境、`runCli(cwd, args, overrides)` を提供する。Git リポジトリ生成と Git・CLI 実行の helper は共有し、テストファイルごとに重複定義しない。環境変数の検証には明示的な override を使用する。

テストは出力、終了コード、参照、worktree、設定、lease を観測して契約を検証する。環境変数と非対話条件のテストは `src/cli.ts` を入口とする。コマンド内部の分岐を検証するテストはコマンド関数を直接呼び出してよい。

### コマンドと共通処理の受け入れ基準

| 対象 | 条件と期待結果 |
| --- | --- |
| cleanup の分類 | マージ済み head、取り込み済み tip、パッチ一致を検証し、fork・管理範囲外・独自変更・照会失敗から対象を保護する。差分末尾の空白を含めて比較する |
| cleanup の競合 | 分類後の OID 変更、OID 不変の実行元・別 worktree での checkout、計画した path の別ブランチへの切り替えを再検証で検出し、対象を保持して報告する |
| cleanup の参照削除 | worktree 削除後に別 worktree で候補が checkout された場合、参照削除前の再検証で拒否する。参照削除時の OID 不一致でも削除しない |
| cleanup の部分失敗 | worktree・参照・設定の失敗を区別する。参照削除成功時は設定を消し、参照削除失敗時は設定を保持する。設定除去失敗は参照削除済みと報告する。prune 失敗でも先行する失敗と完了範囲を表示する |
| restack の更新 | 線形スタックを更新し、保存済み lease で atomic push する。他 worktree の使用と非線形スタックを拒否し、競合後の再開でも lease を保持する |
| start の作成前失敗 | コピーリストを読めない場合、worktree・ブランチを作成する前にエラー終了する |
| start の作成後失敗 | Path と worktree・ブランチ・セッション記録の成否を表示し、作成済み範囲を利用者が特定できる |
| copy の安全性 | dry-run と本実行が symlink・特殊ファイル・`.git`・境界外を同じ走査で判定する。dry-run は拒否予定を表示し、本実行は symlink をコピーせず正常終了する。書き込み直前の配置先検査も行う |
| discard | locked、他 worktree の所属ブランチ、確認後の状態変化を拒否する。リモート・worktree・ローカル参照・設定の削除順序と段階別の失敗状態を検証する |
| init | `init --base-branch main` は `baseBranch: main` を保存する。引数なしではベースを保存せず、`origin/HEAD` があれば候補を案内する。既存設定を上書きしない |
| config check | ベース、ベース省略時の入力条件、branch・worktree の命名方式を表示し、命名スクリプトを実行しない |
| list | 複数セッションと未管理 worktree を用意し、path・root・stack・現在ブランチ・dirty と終了コード `0` を検証する。壊れたセッション情報は未管理として表示し、通信しない |
| ヘルプ・対話・doctor | スタック番号の意味、boolean 環境変数の有効化と解除、命名ツールの任意要件を仕様どおりに表示する。外部診断をそのまま出力しない |
| 共通処理 | CLI 本体のプロセス実行を集約し、patch-id の空白、worktree の locked、パスの同一・子孫判定、Git バージョン判定の各契約を満たす |
| UI カタログ | 収録した discard・skills のケースがそれぞれのコマンド分類に表示される |
| JSON 応答検証 | 正常な応答を処理し、不正な型・構造を明示的な検証で扱う |
| インストーラー | symlink・非通常ファイルへの配置を拒否し、失敗時は既存ファイルを保持する。検証済み成果物を staging から rename で配置する |

### CLI 経由の非対話検証

環境変数は各ケースに必要なものだけを設定する。restack はベース指定済みの有効なセッション、cleanup は削除候補のあるリポジトリを用意する。

| コマンド・入力 | 期待結果 |
| --- | --- |
| `restack`、`PUSH`・`DRY_RUN` は unset | 非ゼロ終了。fetch 未実行、参照・lease 不変。push 対象ゼロにも適用 |
| `restack`、`PUSH=1` | `--push` と同じく rebase・push に成功。unset によって事前拒否に戻る |
| `restack`、`DRY_RUN=1` | `--dry-run` と同じく終了コード `0`。fetch・参照・lease を変更しない |
| `restack`、`PUSH_ONLY=1 PUSH=1` | 保存済み lease と未 push の変更を用意し、rebase・lease 再取得なしで push に成功。lease を除去。`PUSH_ONLY` の unset で通常の restack 経路に戻る |
| `cleanup`、`DRY_RUN=1` | `--dry-run` と同じく終了コード `0`。fetch・参照・worktree を変更しない |
| `cleanup --yes`、`DRY_RUN` は unset | 削除成功 |
| `cleanup`、dry-run・確認省略の指定なし | TTY エラーで非ゼロ終了。参照・worktree を削除しない。分類時の fetch は許容する |

### TTY 上の検証

対話の検証では、固定 devShell の TTY 上で `bun run dev doctor --interactive` に肯定・否定・Ctrl-C を与える。いずれも終了コード `0` と参照不変を確認する。

ベース入力は、CLI・環境変数・設定のベース指定を省いて `bun run dev restack --dry-run` で検証する。`origin/HEAD` の有無による候補を確認し、Enter による確定・Ctrl-C のいずれも終了コード `0` で参照・lease が変わらないことを確認する。

restack の push 確認は、ローカル bare origin と、rebase により OID が変わり push が必要になる独立したセッションを入力ごとに用意する。`PUSH`・`PUSH_ONLY`・`DRY_RUN` は unset とし、rebase と push が正常に実行できる状態で `bun run dev restack --base-branch origin/main` を実行する。

| push 確認への入力 | 終了コード | ローカル参照 | origin の参照 | lease |
| --- | --- | --- | --- | --- |
| 肯定 | `0` | rebase 後の OID | rebase 後の OID に更新 | 除去 |
| 否定 | `0` | rebase 後の OID を保持 | 不変 | 再開用に保持 |
| Ctrl-C | `0` | rebase 後の OID を保持 | 不変 | 再開用に保持 |

いずれも元の checkout ブランチへ復帰する。push 確認時点では rebase が完了しているため、否定・Ctrl-C の検証ではローカル参照が rebase 後の状態であることを確認する。

## 検証の入口

| 証拠 | 実行方法 |
| --- | --- |
| 整形・lint・型・テスト・ビルド・成果物照合 | `./scripts/check.sh` |
| 端末表示 | `nix develop --no-update-lock-file --command bun run ui:catalog` で収録し、表示を確認して `tests/fixtures/ui-baseline.json` を明示的に採用する |
| 対話 | 本書「TTY 上の検証」に従って入力・終了コード・状態を確認する |

検証結果は [検証記録](verification.md)に、実行した環境・入力・観測結果と未検証範囲を区別して記載する。開発時の変更単位とPRの記載事項は [作業規約](../AGENTS.md)に従う。
