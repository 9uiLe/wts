# プロジェクト設定

`.wts.json` でベースブランチ、worktree の配置、命名方法を共有します。初回の作成とコミットは [プロジェクトの初期化](../README.md#プロジェクトを初期化する)に従ってください。

## 設定ファイルの探索

実行中の worktree のルートを優先し、なければメインチェックアウトのルートを探します。操作を決定する設定ファイルを特定できるよう、見つかった一つの `.wts.json` を使い、複数の設定はマージしません。

設定が必要なのは `start`・`stack`・`restack`・`cleanup`・`discard`・`list` と、ファイル指定なしの `config check` です。どちらの場所にもなければエラーになります。`init`・`doctor`・`skills`・ヘルプ・バージョン表示は設定なしで使えます。

## 設定項目

命名スクリプトを使う設定例です。スクリプトを使わない場合は `naming` を省略するか `{}` にします。

```json
{
  "baseBranch": "main",
  "worktreeDirectory": "../project-worktrees",
  "naming": {
    "branch": {
      "script": "./scripts/name-branch.py",
      "prompt": "作業内容からブランチ用の名前を返してください。"
    },
    "worktree": {
      "script": "./scripts/name-worktree.py",
      "prompt": "作業内容からディレクトリ用の名前を返してください。"
    }
  }
}
```

| 項目 | 型 | 内容・省略時 |
| --- | --- | --- |
| `baseBranch` | 空でない文字列 | ローカルのベースブランチ名。操作別の既定値は [ベースブランチ](#ベースブランチ)を参照 |
| `worktreeDirectory` | 空でない文字列 | 絶対パスまたはメインチェックアウト基準の相対パス。既定はメインの絶対パスに `-worktrees` を付けた場所 |
| `naming` | オブジェクト | 命名規則。省略時は外部コマンドを使わない |
| `naming.branch` | オブジェクト | start のブランチ名と stack の接尾辞を生成。省略時は日本時間の日付＋UUID |
| `naming.worktree` | オブジェクト | start のディレクトリ名を生成。省略時はブランチ名の `/` を `-` に置換。stack では使わない |
| `naming.*.script` | 空でない文字列、必須 | 実行可能なスクリプトへのパス。相対パスは読み込んだ設定ファイルの所在ディレクトリが基準 |
| `naming.*.prompt` | 文字列 | スクリプトに渡す文章。省略時は空文字 |

不明な項目、型違い、`null`、存在しない・実行できないスクリプトはエラーです。`naming.branch`・`naming.worktree` を指定する場合は `script` が必要です。`~`・環境変数・シェル式は展開しません。スクリプトには shebang と実行権限を設定してください。

### ベースブランチ

`baseBranch` は `main`、`release/stable` のように `origin/` なしで指定します。Git で有効なローカルブランチ名が必要ですが、設定検査では参照の存在までは要求しません。

`start`・`restack` は `--base-branch`、`BASE_BRANCH`、明示された設定の `origin/<baseBranch>` の順に優先します。すべて未指定なら対話で、候補を使うか別の参照を入力するか選びます。候補はローカルの `origin/HEAD` が指す参照、なければ `origin/main` です。`--format json` を含む非対話では設定または上書きの指定が必要です。

`cleanup` は設定したローカルベースを保護し、対応する `origin/<baseBranch>` への取り込みを判定します。省略時は `main` と `origin/main` を使い、`BASE_BRANCH` では変わりません。通常実行ではこのベースを origin から fetch します。

リモートの既定ブランチは作業基準と一致するとは限らず、cleanup の保護対象にも使うため、`init` は明示したベースだけを保存します。`origin/HEAD` は未指定時の候補として案内するだけです。

### worktree の配置と管理範囲

相対の作成先は、どの worktree から操作してもメインチェックアウトが基準です。存在しないパスも指定できますが、既存の親が書き込み可能なディレクトリである必要があります。メインチェックアウトそのものと Git の管理領域は指定できません。リポジトリ内に置く場合は `.gitignore` に追加してください。

この場所は cleanup・discard の管理範囲にもなるため、worktree 専用のディレクトリを指定します。作成先を変更すると旧配置は現在の管理範囲から外れます。stack・restack・discard は start が記録したセッションを必要とし、手動で作った worktree は対象外です。

### 既定の命名

スクリプトがなければ、セッションのブランチ名は日本時間の `YYYYMMDD-<UUID>`、worktree 名は同じ名前です。UUID は作成ごとに生成し、AI や外部の命名コマンドは呼びません。既存ブランチ・パスとの衝突は上書きせずエラーにします。

スタックブランチは `<root>-pr<n>-<YYYYMMDD-UUID>` です。`root` はセッション作成時のブランチ、`n` は GitHub の PR 番号とは独立したスタック番号です。スクリプトを設定しても、所属を識別する `<root>-pr<n>-` は固定です。

## 設定の検査

リポジトリ内では `wts config check` を使います。ファイルを明示するとリポジトリ外でも検査でき、相対の作成先はそのファイルのディレクトリを基準にします。

```bash
wts config check /path/to/project/.wts.json
```

解決された設定を表示し、JSON 構文、既知の項目、型、パス、スクリプトの実行権限を検査します。成功は終了コード `0`、エラーは `1` です。スクリプトは実行しないため、そのロジック、AI の応答、内部で使うコマンドは検査しません。Git・gh と認証の検査には `wts doctor --check` を使います。

## 管理外ファイルのコピー

`start` は実行元 worktree のルートにある `.worktree-copy` を読み、新しい worktree へファイルをコピーします。コピー元からの相対パス・glob を一行ずつ書き、空行と `#` 以降のコメントは無視します。

```text
.env.local
.claude/skills/*/skills/
```

コピー元は、ベースをローカルブランチ名で指定した場合はそのブランチの worktree、該当しなければメインチェックアウトです。`--copy-from` または `COPY_FROM` で変更でき、相対パスは実行元 worktree のルートが基準です。

リストがなければコピーせず、存在するリストを読めなければ worktree・ブランチを作る前に終了します。コピー元に存在しないパスはスキップします。シンボリックリンク、特殊ファイル、`.git`、絶対パス・`..`・コピー元や配置先の境界外は許可しません。dry-run では拒否予定を表示し、本実行では該当項目を警告付きでスキップします。これらの拒否だけで start 全体を失敗にはしません。

start の作成後に失敗しても、自動では元に戻りません。表示された Path・ブランチと、worktree・ブランチ・セッション記録の作成済み範囲を確認してから再開してください。

## 命名スクリプトの入出力

スクリプトは設定ファイルの所在ディレクトリで直接起動し、引数ではなく JSON を標準入力で一度渡します。

| 項目 | 内容 |
| --- | --- |
| `kind` | `branch` または `worktree` |
| `task` | `--task` または対話で入力した作業内容 |
| `prompt` | 命名設定の `prompt`。省略時は空文字 |
| `date` | 日本時間の `YYYYMMDD` |
| `uuid` | 命名時に生成した UUID |
| `defaultName` | スクリプトを使わない場合の名前 |
| `branch` | worktree 命名時に確定済みのブランチ名 |
| `rootBranch` | stack のセッションルートブランチ名 |
| `prNumber` | stack の番号。文字列 |

適用しない項目は省略します。スクリプト未設定なら作業内容の対話はなく、設定した場合は空の作業内容でも実行します。対話では「スキップ」で空の作業内容を選び、「入力する」を選んだ場合は続く質問で作業内容を入力します。`--format json` を含む非対話では `--task` が必要で、空の作業内容は `--task ''` で指定します。

標準出力に名前を一行だけ出力し、終了コード `0` を返してください。start の branch 出力は最終ブランチ名、stack の branch 出力は固定の `<root>-pr<n>-` に続く名前です。worktree 出力は単一ディレクトリ名で、絶対パス、`/`、`\`、`.`、`..`、`.git` は使えません。

ブランチ名は Git の規則で検証します。非ゼロ終了、空出力、複数行、不正な名前は作成前にエラーとなり、既定名へ置き換えません。標準エラーは wts のエラー表示へ転載しません。

`--dry-run` でも予定名を得るためにスクリプトを実行します。通信や副作用、AI の利用方法はスクリプト側の責任です。設定だけを調べる場合は `config check` を使ってください。

## Claude で作業内容から命名する例

[サンプルスクリプト](examples/name-with-claude.py)を対象プロジェクトの `scripts/name-with-claude.py` へコピーします。この例は Python 3 と認証済み Claude CLI を使い、`claude -p --model haiku` で命名します。wts の既定の命名にはどちらも不要です。

```bash
chmod +x scripts/name-with-claude.py
```

既存の `.wts.json` の `naming.branch` に、次のオブジェクトを設定します。

```json
{
  "script": "./scripts/name-with-claude.py",
  "prompt": "作業内容からブランチ用の英語スラッグを生成してください。英小文字・ハイフンで50文字以内とし、スラッグだけを一行で返してください。説明・装飾・質問は不要です。"
}
```

50 文字はこのサンプル固有の条件で、wts の制限ではありません。start は `YYYYMMDD-<slug>`、stack は `<root>-pr<n>-<slug>`、worktree はブランチと同じ名前になります。worktree 名を別に生成する場合は `naming.worktree` にスクリプトと用途に合うプロンプトを設定してください。
